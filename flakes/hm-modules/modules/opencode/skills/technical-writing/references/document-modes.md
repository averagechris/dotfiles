# Choose the document mode

Diátaxis separates documentation by reader need. Pick the dominant mode before drafting. When a document must serve another need, split the material into a clearly labeled section or linked document rather than switching modes without warning.

## Tutorial

A tutorial helps a learner complete a concrete outcome by doing the work. State what the learner will build or run. Provide a safe path, visible checkpoints, and the expected result after meaningful steps. Keep background brief and link to explanation or reference material.

## How-to

A how-to helps a competent reader reach a specific goal. Start from the reader's situation, state prerequisites, and give the shortest reliable procedure. Include necessary choices and recovery steps, but move teaching detours and broad background elsewhere.

## Reference

Reference material supports lookup. Match the structure and names of the code, API, command, or configuration it describes. Cover accepted values, defaults, limits, outputs, errors, and interactions needed for correct use. Generate facts from code when practical.

## Explanation

Explanation answers a bounded question about why a system works as it does. Cover context, constraints, history, alternatives, and tradeoffs. It may express a reasoned view, but it should distinguish evidence from interpretation. Link procedures instead of embedding step-by-step instructions.
